# Diffusion Language Models for Lean 4 Proof Repair — Starting Bibliography

Compiled 2026-05. Scope: papers needed to motivate, position, and benchmark a project that corrupts a compiling Lean file at density rho, denoises it with a diffusion LM, and uses Lean's type checker as the success oracle.

## 1. Discrete / text diffusion language models

The relevant family is **masked / absorbing-state discrete diffusion**, because proof repair is naturally framed as conditional infilling under a known-clean theorem statement. SEDD established that discrete diffusion can be trained at GPT-2 scale; MDLM and MD4 simplified the objective and closed the AR perplexity gap; LLaDA and Mercury show the recipe scales to instruction-tuned 7B+ models, and Mercury / DiffuCoder / Dream-Coder are the first code-trained diffusion LMs. Diffusion-LM and DiffuSeq are older continuous-embedding work but introduce the controllability / seq2seq framings most relevant to "edit this proof."

- **Diffusion-LM Improves Controllable Text Generation** (Li, Thickstun, Gulrajani, Liang, Hashimoto, 2022, arxiv:2205.14217) — first non-AR diffusion LM with explicit controllable-generation experiments; the conceptual ancestor of treating proof repair as constraint-conditioned denoising.
- **DiffuSeq: Sequence-to-Sequence Text Generation with Diffusion Models** (Gong et al., 2022, arxiv:2210.08933) — seq2seq diffusion; supports the "input = corrupted file, output = clean file" framing as a non-AR translation problem.
- **Discrete Diffusion Modeling by Estimating the Ratios of the Data Distribution (SEDD)** (Lou, Meng, Ermon, 2023, arxiv:2310.16834) — score-entropy objective for genuinely discrete diffusion; the first competitive open-vocabulary discrete diffusion LM.
- **Simple and Effective Masked Diffusion Language Models (MDLM)** (Sahoo et al., NeurIPS 2024, arxiv:2406.07524) — Rao-Blackwellised masked-diffusion loss; the cleanest baseline architecture for our experiments and an easy fine-tuning target on a Lean corpus.
- **Simplified and Generalized Masked Diffusion for Discrete Data (MD4)** (Shi, Han, et al., NeurIPS 2024, arxiv:2406.04329) — generalised state-dependent masking schedules; lets us tune the noising schedule to match the corruption density rho we sweep.
- **LLaDA: Large Language Diffusion Models** (Nie et al., 2025; cf. follow-ups arxiv:2505.16933 LLaDA-V, arxiv:2509.24389 LLaDA-MoE) — first 8B masked-diffusion LM trained as a general-purpose chat model; demonstrates that diffusion LMs can match AR at scale and is the natural backbone for an instruction-tuned proof-repair system.
- **Mercury: Ultra-Fast Language Models Based on Diffusion** (Inception Labs, 2025, arxiv:2506.17298) — Mercury Coder Mini/Small, the first commercial-scale diffusion *code* LM; an obvious closed-source baseline. Their parallel decoding lets us test repair at high rho cheaply.
- **DiffuCoder: Understanding and Improving Masked Diffusion Models for Code Generation** (Gong et al., Apple, 2025, arxiv:2506.20639) — 7B masked-diffusion code LM with coupled-GRPO RL; the strongest *open* code-diffusion baseline and the best candidate to fine-tune on Lean.
- **Dream-Coder 7B: An Open Diffusion Language Model for Code** (Xie et al., 2025, arxiv:2509.01142) — open discrete-diffusion code LM with emergent any-order generation; the "any-order" property is exactly what proof repair needs because corruptions are scattered.
- **DreamOn / TreeDiff / CoDA** (2025, arxiv:2602.01326, arxiv:2508.01473, arxiv:2510.03270) — recent variable-length and AST-guided extensions; relevant if we want the model to handle insertion/deletion corruptions, not just substitution.

## 2. Neural theorem proving / Lean

The current SOTA in Lean is dominated by AR models with proof search (DeepSeek-Prover-V2, Goedel-Prover-V2). We need these as **autoregressive baselines** for the rho sweep. Note: none of these systems repair an entire corrupted file — they generate proofs token-by-token from the goal. That is the gap we want to exploit.

- **Generative Language Modeling for Automated Theorem Proving (GPT-f)** (Polu, Sutskever, 2020, arxiv:2009.03393) — origin paper for transformer + best-first search on formal proofs; historical reference for the AR-prover paradigm.
- **MiniF2F: a Cross-System Benchmark for Formal Olympiad-Level Mathematics** (Zheng, Han, Polu, 2021, arxiv:2109.00110) — the standard 244+244 Lean/Isabelle benchmark; we will adapt theorem-only subsets of miniF2F-Lean as fixed targets when sweeping rho.
- **LeanDojo: Theorem Proving with Retrieval-Augmented Language Models** (Yang et al., NeurIPS 2023, arxiv:2306.15626) — open Lean toolkit, ReProver, and a 98K-theorem Mathlib-derived dataset; the natural source of training data for our diffusion fine-tune.
- **Llemma: An Open Language Model for Mathematics** (Azerbayev et al., 2023, arxiv:2310.10631) — Code-Llama continued-pretrained on Proof-Pile-2; an obvious dense AR baseline at 7B/34B.
- **InternLM-Math** (Ying et al., 2024, arxiv:2402.06332) and **InternLM2.5-StepProver** (Wu et al., 2024, arxiv:2410.15700) — bilingual math LM with strong miniF2F results; another AR baseline and a source of formal-step data.
- **Lean Copilot** (Song, Yang, Anandkumar, 2024, arxiv:2404.12534) — in-editor tactic / proof suggestion; relevant as the deployment target for an eventual diffusion-based repair tool.
- **Lean-STaR: Learning to Interleave Thinking and Proving** (Lin et al., 2024, arxiv:2407.10040) — informal CoT before each tactic; suggests we should let the diffusion model emit comments / thoughts in addition to code during denoising.
- **Goedel-Prover** (Lin et al., 2025, arxiv:2502.07640) and **Goedel-Prover-V2** (2025, arxiv:2508.03613) — current open-source SOTA on miniF2F (84.6% pass@32 at 8B); strong AR baseline at the same parameter scale as DiffuCoder/Dream-Coder.
- **DeepSeek-Prover-V2** (DeepSeek-AI, 2025, arxiv:2504.21801) — 671B Lean prover at 88.9% miniF2F via RL on subgoal decomposition; the absolute SOTA reference even though we cannot match its scale.

## 3. Proof repair specifically

This is the closest cluster. Ringer's group built proof repair as a discipline (PRISM, type-equivalence repair); Baldur reframed it for LLMs in Isabelle/HOL; APOLLO is the live SOTA in Lean. **None of these is a diffusion model**: they are AR generation conditioned on `(goal, error message, broken proof)`. So the diffusion framing is genuinely open.

- **Proof Repair across Type Equivalences** (Ringer et al., POPL 2021, arxiv:2010.00774) — symbolic proof-term transformations; the canonical reference for "what counts as proof repair" before learning-based methods.
- **Baldur: Whole-Proof Generation and Repair with Large Language Models** (First, Rabe, Ringer, Brun, FSE 2023, arxiv:2303.04910) — fine-tuned Minerva on Isabelle/HOL; explicitly defines a *repair* model conditioned on a previous failed proof + error message. The closest prior art conceptually and the paper our work most directly builds on.
- **PRISM: Proof Repair Infrastructure for Supervised Models** (Reichel, Henderson, Touchet, Gardner, Ringer, ITP 2023) — Coq-side dataset of repair pairs mined from Git history; the model for how we should build a Lean repair benchmark from Mathlib commits.
- **Proof Repair across Quotient Type Equivalences** (Ringer et al., 2023, arxiv:2310.06959) — extension of the symbolic line; useful as a non-learned baseline for "principled" repair.
- **APOLLO: Automated LLM and Lean Collaboration for Advanced Formal Reasoning** (Ospanov, Farnia, Yousefzadeh, 2025, arxiv:2505.05758) — agentic Lean-compiler-in-the-loop repair; 84.9% on miniF2F at <100 samples. The current SOTA repair system in Lean and our most important head-to-head comparison.
- **PALM: Proof Automation with Large Language Models** (Lu et al., 2024) — symbolic-LLM hybrid that repairs failed proofs with rule-based fixes; baseline for "do we need diffusion at all, or just compile-and-fix?".

## 4. Code editing / repair as denoising

The "diffusion-as-repair" framing already exists for ordinary code, in two recent Microsoft papers. **One of these is essentially the program-synthesis analogue of what I want to do for Lean — flag for direct comparison.**

- **CodeFusion: A Pre-trained Diffusion Model for Code Generation** (Singh et al., Microsoft, EMNLP 2023, arxiv:2310.17680) — first general-purpose code diffusion model; small (75M) but matches AR systems orders of magnitude larger on top-3 NL-to-code accuracy.
- **Diffusion is a Code Repair Operator and Generator** (Singh, Verbruggen, Le, Gulwani, Microsoft, 2025, arxiv:2508.11110) — **DIRECT PRIOR ART**: explicitly proposes adding noise to broken code and resuming the diffusion process as a last-mile repair operator. Frames this in Python; my project is the Lean / formal-verification analogue. Must cite as the originator of "diffusion = repair" and differentiate by (a) Lean type-checker as oracle, (b) sweep over corruption density, (c) variable-length structured (proof) target.
- **CodeDiffuSe: Masked Diffusion for Structure-Aware Code Completion and Repair** (Springer / KSU CIS, 2025) — masked diffusion fine-tuned for AST-aware completion *and* repair; second piece of direct prior art for "diffusion as repair", targeting completion + bug fixing.
- **AlphaRepair: Zero-shot Repair via CodeBERT MLM** (Xia, Zhang, ESEC/FSE 2022) — masks suspicious lines and infills with CodeBERT; the original "MLM-as-repair" baseline and the natural ablation ("does diffusion beat plain MLM infilling?").
- **Impact of Code Language Models on Automated Program Repair (CLM)** (Jiang, Liu, Lyu, Tan, ICSE 2023) — fine-tuned code LMs on Defects4J; relevant for choosing how to evaluate repair success rates.
- **HumanEvalFix / HumanEvalPack** (Muennighoff et al., 2023; cf. arxiv:2308.07124, OctoPack) — 164 hand-introduced bugs across 6 languages; the standard benchmark we should mirror in Lean (synthetic theorem-internal corruptions calibrated by category).
- **Robust Learning of Diverse Code Edits (NextCoder / SeleKT)** (Aggarwal et al., 2025, arxiv:2503.03656) — synthetic-edit data pipeline + fine-tuning method; their data-generation strategy is portable to Lean (deficient-then-edit).

## 5. Density-of-errors / robustness curves

This is the thinnest cluster — the natural-language and vision robustness literatures sweep noise levels routinely, but the *code / proof* literature almost never reports a corruption-density curve. That is part of why this project is interesting.

- **Robustness of Large Language Models to Perturbations in Text** (Singh, Vepa, Vepa, 2024, arxiv:2407.08989) — sweeps character-/word-level noise rates and reports degradation curves; the methodological template for our rho-sweep, but on natural language only.
- **Certified Robustness for Large Language Models with Self-Denoising** (Zhang et al., 2023, arxiv:2307.07171) and **Self-Denoised Smoothing** (Ji et al., 2024, arxiv:2404.12274) — frame LLM denoising of corrupted inputs as a tool for certified robustness; relevant if we want to claim robustness guarantees from rho-vs-success curves.
- **Where Do Prompt Perturbations Break Generation?** (2026, arxiv:2605.01605) — segment-level robustness in LoRA-tuned LMs; methodology for *where* in a sequence corruption is most damaging — directly applicable to "is the broken statement, the lemma, or the tactic the bottleneck?".
- **CodeFusion / "Diffusion is a Code Repair Operator"** (above) — both papers report *some* degradation-vs-noise data for code diffusion; the closest existing rho curves but neither sweeps rho systematically.
- **Benchmarking Neural Network Robustness to Common Corruptions and Perturbations** (Hendrycks, Dietterich, ICLR 2019) — origin of the corruption-severity curve methodology in vision; cite as the conceptual ancestor of the rho-sweep evaluation.

## 6. Energy-based models for sequence repair / proof search

The Lean type checker is itself a hard energy function — `E_lean(file) = 0` if the file elaborates and `+inf` otherwise — so any learned proof-repair sampler implicitly composes a smooth `E_theta(file)` with this discontinuous oracle. This cluster collects the prior art for that composition: residual / discriminative EBMs that bolt a sequence-level energy onto a pretrained AR LM, score-based formulations that extend gradient-based sampling to discrete data, and GFlowNets that amortise MCMC over compositional objects and have already been pointed at Lean. Read in this order, the path is: classical EBMs for text, then discrete-domain score matching, then GFlowNets as a tractable replacement for Langevin on token sequences, then the one paper (Proof Flow) that puts a GFlowNet in the proof-search loop. Together they motivate two concrete design choices for this project: (a) train `E_theta` as a residual on top of the diffusion repair model, and (b) treat denoising as MCMC with `E_lean` as a constraint rather than as a fixed-budget reverse process.

- **Residual Energy-Based Models for Text Generation** (Deng, Bakhtin, Ott, Szlam, Ranzato, 2020, arxiv:2004.11714) — sequence-level EBM trained as a residual on top of an AR LM via NCE; the canonical recipe for "add a global discriminator to a locally normalised generator" and the natural template for adding an `E_theta(proof_file)` term to a diffusion repair model.
- **Your Classifier is Secretly an Energy Based Model (JEM)** (Grathwohl, Wang, Jacobsen, Duvenaud, Norouzi, Swersky, ICLR 2020, arxiv:1912.03263) — reinterprets a discriminative classifier as an EBM over the joint distribution; provides the conceptual bridge for treating any "compiles vs. does-not-compile" Lean classifier as the gradient field of an energy and sampling against it.
- **Concrete Score Matching: Generalized Score Matching for Discrete Data** (Meng, Choi, Song, Ermon, NeurIPS 2022, arxiv:2211.00802) — defines a discrete analogue of the Stein score over a neighbourhood structure; the score-matching foundation that SEDD (cluster 1, arxiv:2310.16834) builds on, and the bridge between discrete diffusion and the EBM literature.
- **Flow Network based Generative Models for Non-Iterative Diverse Candidate Generation (GFlowNet)** (E. Bengio, Jain, Korablyov, Precup, Y. Bengio, NeurIPS 2021, arxiv:2106.04399) — original GFlowNet paper; frames "convert an energy function into a diverse-sample generator" as a flow-matching objective and explicitly amortises MCMC over compositional objects, exactly the regime proof-repair lives in.
- **GFlowNet Foundations** (Bengio, Lahlou, Deleu, Hu, Tiwari, Bengio, 2021, arxiv:2111.09266) — extends GFlowNets to joint / conditional / Pareto distributions and partition-function estimation; the reference for treating a GFlowNet as a tractable surrogate for sampling under modular energies (e.g. learned LM energy + hard Lean energy).
- **Generative Flow Networks for Discrete Probabilistic Modeling (EB-GFN)** (Zhang, Malkin, Liu, Volokhova, Courville, Bengio, ICML 2022, arxiv:2202.01361) — jointly trains a GFlowNet with an energy model so the GFlowNet samples from the energy distribution while the energy is learned by approximate MLE on its negatives; the cleanest blueprint for co-training `E_theta` with a repair sampler on discrete tokens.
- **COLD Decoding: Energy-based Constrained Text Generation with Langevin Dynamics** (Qin, Welleck, Khashabi, Choi, NeurIPS 2022, arxiv:2202.11705) — unifies hard and soft text-generation constraints as terms in an energy function and samples with Langevin dynamics over a relaxed token simplex; the closest prior art for "compose a learned LM energy with a hard external constraint" and a direct methodological analogue for `E_theta + E_lean`.
- **Proof Flow: GFlowNet Language Model Tuning for Formal Reasoning** (Ho, Zhu, Chen, Jain, Malkin, Zhang, 2024, arxiv:2410.13224) — the only existing GFlowNet-x-Lean work; fine-tunes an LM as a GFlowNet over Lean proof trajectories with the verifier as terminal reward, demonstrating better exploration than reward-maximising RL. The single most relevant prior art for this project and the obvious head-to-head when generalising from per-tactic search to whole-file repair.

## Gaps

1. **No diffusion-vs-AR rho sweep on formal proofs.** Diffusion-as-code-repair (arxiv:2508.11110) and diffusion code LMs (DiffuCoder, Dream-Coder) exist but have never been evaluated with a type-checker oracle, never on Lean, and never with a controlled corruption-density axis. Lean repair systems (Baldur, APOLLO) use AR LMs and condition on a single error message rather than denoising a whole corrupted file.
2. **No "maximum recoverable density" metric.** The proof-repair literature reports pass@k at fixed difficulty. No one has reported, for any prover, the rho* at which success falls below 50%. This is a clean new axis of comparison and may correlate better with practical usefulness (e.g. surviving a Mathlib refactor) than miniF2F pass-rate.
3. **No structure-aware corruption taxonomy for proofs.** HumanEvalFix has six bug categories for Python; there is no analogue for Lean (e.g. "wrong tactic", "wrong universe level", "term-mode vs tactic-mode mismatch", "missing have"). Building this taxonomy is a contribution in itself and lets us report per-category rho curves.
4. **No exploitation of the type checker as a denoising stop signal.** Existing diffusion code repair runs a fixed number of denoising steps; existing Lean LLM systems re-prompt on compile failure. Nobody has wired Lean's elaborator into the diffusion sampler as an early-stopping / guidance signal — a concrete algorithmic contribution this project could make beyond the empirical rho-curve.
5. **No EBM treatment of the verifier-as-energy, and only one GFlowNet-x-Lean paper.** Proof Flow (arxiv:2410.13224) is the sole prior work pointing a GFlowNet at Lean, and it operates per-tactic from a goal state rather than over a corrupted whole-file artifact; nobody has trained a residual sequence-level energy `E_theta(file)` (Deng-style, arxiv:2004.11714) on top of a Lean diffusion LM, and nobody has run COLD-style Langevin (arxiv:2202.11705) or EB-GFN-style amortised MCMC (arxiv:2202.01361) with the type checker as the hard-constraint term. Framing proof repair explicitly as sampling from `E_theta + E_lean` is an unclaimed slot that connects this project to the wider EBM / GFlowNet literature rather than only the diffusion-LM one.
